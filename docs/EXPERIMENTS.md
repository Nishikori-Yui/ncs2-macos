# 不涉及摄像头的实验方向

已跑通的基础是：macOS 原生 arm64 主机 → OpenVINO 2022.3.2 MYRIAD → NCS2。现在已实现算子/shape IR 测试集和 USB 生命周期采样；其余计划状态见 IMPLEMENTATION.md。

| 方向 | 可以做的东西 | 第一项可验证实验 |
| --- | --- | --- |
| USB 设备考古 | 描述符、USB 2/3 连接差异、固件启动前后 PID 和端点变化 | 先记录只读状态，再在显式启动窗口取样；不向任意端点盲发数据 |
| XLink 协议观察 | 对已有开源 host 层加结构化日志，观察 stream、buffer、超时与重枚举 | 记录一次已知模型的 boot/compile/infer/close 生命周期 |
| 性能实验室 | 冷启动、预热、p50/p95、张量大小、重复请求、并发请求 | 已有四尺寸 ReLU 和三种卷积延迟；并发和主机预处理对照待做 |
| 数值实验 | FP32 输入与设备结果误差、算子组合、静态 shape 限制 | 为每个算子编写主机参考结果和容差；分别报告编译/执行失败 |
| 离线音频 | WAV 文件关键词或环境声分类 | 先验证声谱输入的静态小 CNN；不需要摄像头或麦克风采集 |
| 时间序列 | 合成传感器数据的异常检测、自编码器 | 使用固定窗口的小型网络并检验异常分数 |
| 现代 macOS API | Python/Swift 前端调用独立 arm64 worker | 版本化 JSON 请求/结果，错误码明确，进程隔离旧 runtime ABI |

性能报告应同时保留模型、shape、数据类型、USB 连接速率、预热次数、样本量和误差，不把 1x4 ReLU 的毫秒数外推为通用推理速度。功耗或能效需要额外测量，不能从延迟推算。

优先顺序建议：稳定工具链 → 算子/shape 小型测试集 → USB 状态与延迟扫描 → 独立 worker API → 音频或时序模型。自定义 Myriad 内核编译器和现代大模型不在已验证能力内。
